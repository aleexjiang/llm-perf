# trace-real-16：真实 agent 会话样本（脱敏）

**128 条**真实 LLM 调用快照，覆盖**单次 prompt 20k–500k tokens** 六档，用于 `dataset.mode: trace` 回放。

- **文件**：`trace-real-16.json.gz`（gzip，12.6 MB；解压后约 46 MB，JSON / sharegpt 格式）
- **格式识别**：`sharegpt`（`conversations[].from` = `system` / `user` / `assistant` / `tool`，tool 消息带 `tool_call_id`）
- **来源**：内部 LLM 可观测平台（OTel 链路）2026-09-03 ~ 2026-09-16 的真实调用，**已于 2026-09-17 二次脱敏 + 场景配平**
- **场景构成**：非 coding 24 条（19%）/ coding 104 条（81%）——非 coding 侧已吃满数据源存量，配平口径见下节
- **入口分布**：CodeBuddyIDE 53 / WorkBuddy 48 / CLI 22 / app_cloud 5
- **模型覆盖**：glm-5.3-flash 60 / hy3 24 / gpt-5.6-luna 18 / hy4-preview 14 / gpt-5.6-terra 4 / glm-5v-turbo 3 / deepseek-v4.1-flash 3 / deepseek-v4-pro 2
- **档位分布**：<40k 8 / 40-80k 54 / 80-150k 50 / 150-250k 8 / 250-500k 7 / >500k 1

## 采样口径

1. **会话筛选**：按 `sessionID` 聚合全量 trace（14 天窗口共 154 个会话），只保留**用户轮数 ≥ 3** 的会话——27 个。
2. **场景打标（内容口径，非入口口径）**：逐条读会话首轮 prompt 判定任务类型。**不能按入口分**：
   同一入口下既有编码也有办公，且 WorkBuddy 里跑了不少 llm-perf 工程会话。打标结果：coding 15 个会话 / 非 coding 12 个会话。
3. **快照挑选**：取每个会话**第 3 个用户轮及以后**的 LLM 调用（每会话上限：非 coding 12 / coding 8，优先覆盖不同会话）。
4. **单条内容** = 选中那次调用（`span`，同 trace 内 input tokens 最大者）的**完整 messages 原序**，
   并把该次请求的工具定义拼成一条尾部 `system` 消息（`## Available Tools`），保留真实 prefill 体积与前缀结构。
5. **轮数上限**：会话超过 32 个用户轮的，裁到第 32 轮为止（1 条命中），避免单条体量失控。
6. **只收多轮条目**：部分 span 是「单轮 prompt」（`system` + 1 条 `user` + 工具循环，WorkBuddy craft 模式常见），
   会被 `LoadTrace(min_turns=2)` 直接过滤，因此整批排除（138 个候选中排除 25 个）。

## 场景配平（2026-09-17）

**目标**是让 coding 场景别占大头。实测下来这条目标受数据源硬约束，结论如下，避免后续再走一遍：

| 口径 | 会话数 | 可用快照 | 说明 |
|---|---|---|---|
| 非 coding（≥3 轮） | 12 | 36 | 再经 `min_turns=2` 过滤后**实际可用 24 条** |
| coding（≥3 轮） | 15 | 330+ | 上限受每会话 8 条与档位配额限制 |

- **非 coding 的硬天花板是 24 条**（不是会话数 × 上限）。原因：WorkBuddy craft 模式的 prompt **不携带历史**
  （`system` + 1 条 `user` + 工具循环），第 3 轮及以后的 span 里有相当一部分 `user` 消息数仍为 1，
  被 `min_turns=2` 挡掉——12 个非 coding 会话里有 4 个（baa9f304 / e9a444fc / 8952749b / cf5dec7a）的 12 个候选因此落选。
- **非 coding 工作本身就是短会话**：154 个会话里 89 个只有 1 轮。工单、评估表、周报、文档处理、定时抓取这类任务天然一问一答；
  而 llm-perf / GPU 容器这类工程任务才是长会话。**样本偏 coding 是用法形状决定的，不是抽取偏差。**
- 其它空间（`knot_platform` / `BoxAi` / `ima-copilot` 等 18 个）在本账号 `read_self` 权限下**均为空**，无法横向补样本。
- 因此最终落点：**非 coding 吃满 24 条 / coding 104 条**。若要进一步压低 coding 占比，唯一可行路径是**下调总条目数**
  （例如总 ~28 条可做到 coding 1/8），而非从数据源里再找。
