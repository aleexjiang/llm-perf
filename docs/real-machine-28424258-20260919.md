## 新发现（本轮）

### 1. user 模式重跑对照实验不保证会话轨迹一致（口径澄清）

- 现象（轮 4）：同 `seed_salt` 重跑 t1 组，前 2 轮 prompt 完全一致，第 3 轮起分叉
  （34345 vs 34424）；同输入下 assistant 字符数 481 vs 543。
- 根因：assistant 是被测模型真实采样生成（未传 temperature/top_p，服务端默认采样），
  回复长度随机 → 追加进 history 后下一轮 prompt 自然分叉。**设计使然，非 bug**。
- 影响：① 同配置重跑的"确定性"只覆盖输入构造（user/context），会话轨迹必然分叉；
  ② TTFT 逐轮对照实验不能假设两轮轨迹对齐；
  ③ prefix cache 的动态语义因此每次都不同——这是 user 模式与冻结快照的本质差异，符合设计。
- **改进建议**：增加请求级 `temperature`/`top_p` 配置；轨迹对齐实验显式传 `temperature: 0`。

### 2. probe `chat_nonstream` 对思考模型持续误报（已知形态，建议降噪）

- max_tokens=1 的非流式探测在 Qwen3.8 上 content=""（1 token 进思考块），标准面 8/9。
- probe 路径未带 enable_thinking=false（与压测路径不同口径）；该 FAIL 是探测参数问题
  而非端点缺陷，建议 probe 探测请求同样注入 enable_thinking=false。

### 3. 空回复现象在新部署复现（约 1/60 轮）

- r1-t8 用户1 t9：completion=1、无可见输出、finish=stop——与旧环境一致的长上下文偶发形态；
- 终止逻辑正确触发，会话在 9 轮（turns_range 下限）终止而非继续滚。
- Qwen3.8-27B-FP8 在长上下文下偶发空回复是该模型/部署的固有行为，压测侧已正确处理。
